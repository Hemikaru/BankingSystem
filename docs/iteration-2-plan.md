# Iteration 2 Plan

## Мета ітерації

Розширити базову банківську систему, створену в Lab 34, додавши бізнес-операції, файлове збереження даних, LINQ-запити та механізми розширення архітектури.

## Сценарії, що переходять у реалізацію

### UC-1. Створення рахунку

Сценарій реалізований у Lab 34 та буде збережений без змін як частина основного функціоналу.

### UC-2. Зняття коштів

Користувач може зняти кошти з рахунку за умови достатнього балансу.

### UC-3. Переказ між рахунками

Користувач може виконати переказ між двома рахунками з перевіркою бізнес-правил.

## Класи, які залишаються без суттєвих змін

- Customer
- Transaction
- TransactionType
- CheckingAccount
- SavingsAccount

## Класи та контракти, що будуть розширені

- BankAccount
- AccountService
- IBankAccountRepository
- InMemoryBankAccountRepository

## Заплановані точки розширення

### Factory Pattern

Для створення різних типів рахунків через єдиний механізм.

Майбутні типи рахунків:

- CheckingAccount
- SavingsAccount
- BusinessAccount (можливе розширення)

### Persistence Layer

Заплановано окремий контракт для збереження даних:

- IDataStore<T>
- JsonAccountDataStore

Це дозволить у майбутньому додати XML або базу даних без зміни бізнес-логіки.

## Потенційні ризики

### Дублювання логіки

Існує ризик дублювання перевірок балансу між сервісами та доменними сутностями.

### Слабкі контракти

Поточний репозиторій ще не підтримує видалення та повноцінне керування життєвим циклом сутностей.

### Тестування Persistence

Файлове збереження потребуватиме окремих тестів та перевірки негативних сценаріїв.

### Майбутні інтеграційні тести

Потрібно підготувати сервіси до тестування без залежності від файлової системи.
